# 辛口評価と改善の回し方

UIとバランスをさらに良くするため、**評価する役と直す役を分けて**回す(依頼主の発案)。
定義は `.claude/agents/` にある。

| 役 | 定義 | 書き換え | すること |
|---|---|---|---|
| UIの辛口評価 | `crimon-critic-ui` | しない | 実ブラウザで撮り、画像を見て、重い順に指摘する |
| バランスの辛口評価 | `crimon-critic-balance` | しない | 計測道具で数字を取り、設計の2原則に照らして指摘する |
| 改善 | `crimon-improver` | する(担当ファイルだけ) | 指摘を1件ずつ直し、型・テスト・巡回を通す。pushしない |
| 目隠しの判定 | `crimon-blind-judge` | しない | 左右を伏せた前後画像だけを見て、どちらが良いか答える |

## なぜ分けるのか

- **直した本人は必ず「良くなった」と言う**(`CLAUDE.md`)。評価と判定を、直す役から切り離す
- 評価役は**書き換えられない**ので、「自分で直せる所だけ指摘する」という甘さが入らない
- 判定役は**コードも説明も見ない**。画面だけで決める

## 1周の流れ

```
1. 評価     crimon-critic-ui / crimon-critic-balance(並べて2つまで)
            → 重い順の指摘(最大10件ずつ)
2. 選ぶ     取りまとめ役が、致命・重大から直す物を選ぶ。
            担当ファイルが重ならないように割り振る(同時に2〜3個まで)
3. 直す     crimon-improver に「指摘1件・担当ファイル・使うポート」を渡す
            → 前後の撮影・数字、比較画像のフォルダが返る
4. 判定     画面の変更は crimon-blind-judge に比較画像のフォルダだけを渡す
            → 「新しい版が優れている」と出なかった物は入れない
            バランスの変更は crimon-critic-balance にもう一度測らせる
5. 反映     取りまとめ役がまとめてコミット → PR → CIが4つとも緑 → squashマージ
            お知らせ(compensation.ts の先頭)と引き継ぎ書を忘れない
```

## 決まり

- ポートは担当ごとに分ける(例: 評価UI 5520/5521、改善A 5530/5531、改善B 5540/5541)
- `pkill -f harness.mjs` は使わない。止めるのは自分のポートだけ
- 評価役・判定役のレポートは作業フォルダに置く。**リポジトリへ入れない**
  (終わった指摘の山が残ると、次の人が消していいか判断できない)
- 採点の基準は `docs/visual-quality-rubric.md`(バトル画面)と `docs/design-concept.md`(バランス)。
  基準を変える時は、評価役の定義も一緒に直す
