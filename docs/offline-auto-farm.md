# オフラインバックグラウンド周回（⑧-5-3）

## 方針

iOS Safari/PWA は非表示・完全終了時に JavaScript、タイマー、Service Worker の継続実行を保証しない。そのため、終了中に `BattleEngine` を動かす設計ではない。共通の `backgroundFarmJob` に開始時刻と最終処理時刻を保存し、次回表示時に `now - lastProcessedAt` を計算して、処理権を得た周だけを復帰後に実行する。`visibilitychange`、`pagehide`、`beforeunload` は保存機会として使うが、これらが発火しなくても定期的な1周ごとの保存から復帰できる。

## 基準時間と経過時間

`referenceRunSeconds` はジョブ開始時に固定する。信頼できる実戦所要時間履歴がまだ既存セーブに存在しないため、現在は通常ステージ120秒、装備ダンジョン150秒、育成・ゴールドダンジョン120秒を安全な既定値とした。敵が最も硬くなりやすい装備ダンジョンを長くした。難易度 HARD は1.25倍、HELL は1.5倍である。

将来、実戦クリア時間を記録できるよう `recentClearTimes`（最大直近5件）と中央値計算を実装済みである。単発の高速クリアで加速しない最低値は、通常60秒、装備90秒、育成・ゴールド75秒。現在の同期バックグラウンド戦闘のCPU実行時間は実戦時間ではないため履歴には混ぜない。

計算は次の通り。

```text
elapsed = clamp((now - lastProcessedAt) / 1000, 0, 8時間)
total = accumulatedOfflineSeconds + elapsed
available = floor(total / referenceRunSeconds)
実処理数 = min(available, 希望回数 - 完了回数, ゲーム上実行可能な回数)
余り = total - 実処理数 * referenceRunSeconds
```

余りは `accumulatedOfflineSeconds` に保存して次回へ繰り越す。計上時点で `lastProcessedAt` を現在時刻へ進めて即保存するため、同じ時間を二重計上しない。負の時間は0。巨大な時計ジャンプも最大8時間となる。8時間は睡眠・勤務中の一般的な離席を覆いつつ、満タンまでの自然回復量しか保持できない現行スタミナ制と合わせて数日分の自動消費を防ぐ中間値（4時間より利用者に寛容、12時間より安全）である。希望周回数そのものに固定上限はない。

## 戦闘、資源、報酬

権利を得た周も1周ずつ正式な `BattleEngine` に渡す。編成は開始時の個体IDスナップショットを使い、潜在能力を含む戦闘処理を複製しない。敗北時はその敗北を記録して即終了し、残りを処理しない。勝利報酬は通常と同じ `applyStageClearRewards` / 各ダンジョンの報酬関数を使うため、RNGドロップ、EXP、LvMAX分のEXP再分配、ゴールド、装備、モンスター、経験ピッグ等も共通である。

各周は、実行条件確認、日次枠・スタミナ消費、`inFlight` 保存、戦闘、勝敗、報酬、`completedRuns` 更新、保存の順。支払い済みマーカーを報酬より先に永続化し、報酬と完了位置は同じ同期区間で更新してから保存する。localStorage保存前にクラッシュした場合は支払い済み戦闘から再開し、保存後なら完了位置から進むので二重報酬を避ける。

スタミナは各周で正式な `trySpendStamina` を使う。起動時の自然回復は既存 `applyPassiveStaminaRegen` に任せ、上限まで一度回復した現在値から消費するだけで、「回復→消費」を長期間刻むシミュレーションはしない。ダイヤ、ゴールド、回復アイテムは自動消費しない。現行データモデルには装備・モンスターの所持上限がなく、自動売却も行わない。上限が導入された場合は既存報酬処理の拒否規則に従って停止させる。

## 日次制限、復帰、UI

育成・ゴールドダンジョンは毎周、既存の日次残数を確認する。さらに開始時のJST日付と復帰時の日付が違えば、翌日枠を使う前に `DAILY_LIMIT` で停止する。通常・装備ダンジョンは日付変更だけでは停止しない。

復帰処理は既存のバックグラウンド周回スケジューラへ統合され、1周ごとに `setTimeout` でイベントループへ戻す。巨大同期ループや巨大戦闘ログを保持しない。処理中は「オフライン周回処理中 n / total」、通常時は対象、完了/希望周、残数、基準時間、集計報酬を表示する。「周回を終了」では確定済み報酬を残し、未処理分を消費しない。開始画面にも完全終了後の経過時間処理を明記する。

⑧-5-2と別ジョブは作らず、表示中は通常バックグラウンド処理、非表示中は時間保存、復帰時は時間に応じた処理権を同じ `backgroundFarmJob` で扱う。
