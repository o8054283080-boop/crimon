# 新戦闘状態効果 実装レポート

## 実装概要

9効果（被クリ率ダウン、我慢、反射、復活、無敵、挑発、強化不可、スキル使用不可、被クリ率アップ）を検証専用コードではなく本番の `BattleEngine`、ダメージ計算、対象/AI選択、手動入力、HUDへ統合した。本番モンスターのスキル、倍率、CT、Hit数、対象、ステータスは変更していない。

## 実装場所と既存システムの拡張

- `src/core/skill.ts`: `STATUS` スキル効果、9種の型、BUFF/DEBUFF分類、日本語表示、スキルレベル時のduration更新。
- `src/battle/unit.ts`: `statusEffects`、同名上書き、強化不可ゲート、共通の無敵/シールド/我慢/復活/死亡処理。STRIPもカテゴリBUFFを除去する。
- `src/battle/damage.ts`: 既存の攻撃者実効クリ率に対象側 `+0.50 - 0.30` を加えてclamp。方式Eの係数やHP/DEF係数は変更なし。
- `src/battle/engine.ts`: STATUS付与と命中/抵抗、ログ、実HP損失の取得、反射イベント、CLEANSE、手動スキル制限、挑発強制を統合。
- `src/battle/ai.ts`: スキル使用不可時のスキル1選択、単体敵対象への挑発適用と死亡元の掃除。
- `src/web/views/battleHud.ts` / `battleView.ts`: 既存チップの文字title/仮グリフで9効果を表示し、スキル2/3をdisabled化。

## 特殊処理

致死処理はダメージ適用の一本に集約し、死亡確定前に我慢、次に復活を判定する。復活で `alive` が維持されるため多段ループは残Hitを解決する。無敵は `roundNormalDamage()` 後の適用段階で0にし、シールドも減らさない。

反射元の基準値は `beforeHp - afterHp` で取得する。このためシールド吸収分を除外し、我慢時もHP1までの損失だけになる。各Hitごとに `round(actualHpDamage * 0.25)` するため、総損失へ一度だけ掛けた値との差が丸め誤差として生じ得る。反射は `sourceType: reflect` で再入し、二次反射を禁止する一方、受け手の無敵・我慢・復活・死亡は共通処理する。

挑発元は `sourceId` で1件だけ保持し、再付与で置換する。対象タイプは `SINGLE_ENEMY` のみ強制し、全体、味方、自己は維持する。現行の `TargetType` にはランダム対象が存在しない。

強化不可は型カテゴリでBUFFを判定し、既存の能力BUFF、シールド、免疫、継続回復、新状態BUFFの新規/更新を拒否する。既存効果は削除しない。スキル使用不可は手動ロジック、AI、UIの三層でスキル1だけに制限し、CT配列には触れない。

## UI・アセット・既知事項

専用画像は生成せず、既存の状態チップとフォールバックグリフ、名称tooltipを利用した。将来の仕上げに必要な未作成専用アイコンは9点（被クリ率ダウン、我慢、反射、復活、無敵、挑発、強化不可、スキル使用不可、被クリ率アップ）。

既知事項は、反射がHit単位で整数化されるため合計後25%との間に小さな丸め差があり得ること、現行対象型にランダム対象がないこと、専用アイコンが未作成であること。次は専用アセット、ユーザー決定後の本番スキル割り当て、およびカテゴリAPI名を公開した一括解除スキルの追加が候補となる。
