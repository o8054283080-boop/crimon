## 3. 再付与／延長処理（現行コード）

**3つの異なる方式が共存している。**

### (a) `BUFF` / `DEBUFF`（能力値の増減）— **加算・重ねがけあり**

`src/battle/engine.ts` の付与は、既存を見ずに配列へ足すだけ。

```ts
receiver.effects.push({ stat: effect.stat, amount: buffAmount, remainingTurns: buffTurns, kind: "BUFF" });
```

`src/battle/unit.ts` の `getEffectiveStat` は、同じ `stat` のものを**全部合算**する。

```ts
const totalRate = unit.effects.filter((e) => e.stat === stat).reduce((sum, e) => sum + e.amount, 0);
const multiplier = Math.max(0.1, 1 + totalRate) * passive.multiplier;
```

つまり:

- 攻撃UP30% を2回 → **+60%**
- 防御UP50%（シェルタートル）＋ 防御UP30%（ドラゴン） → **+80%**
- 防御DOWN50% を2回 → **−100% → 下限 `Math.max(0.1, …)` で元の10%**
- クリ率は `Math.min(1, …)` で100%打ち止め、クリダメは下限0のみ

**ターンは長い方に寄せない。**それぞれ独立に減っていくので、
攻撃UP30%(残1T) と 攻撃UP30%(残3T) が同居し、1T後に+30%へ落ちる。

**解除も1つずつ。**`stripBuffs` は `findIndex` で1件取るので、重ねがけは強化解除への耐性にもなっている。
UIも積まれた数だけ印が並ぶ（`buildStatusChips` は `snapshot.effects` をそのまま列にする）。

### (b) `STATUS`（無敵・挑発・強化不可など）— **上書き**

```ts
/** 同名はスタックせず、新しい付与で残りターンと挑発元を上書きする。 */
const index = unit.statusEffects.findIndex((effect) => effect.type === type);
if (index >= 0) unit.statusEffects[index] = next;
```

**長い方ではなく、新しい方で置き換える。**
無敵3T（フェニックス）が残っているところへ無敵1T（ミミック）を重ねると**1Tに縮む。**

### (c) フィールド保持型（スタン・毒・シールド・免疫・回復阻害・暗闇ほか）— **`Math.max`**

```ts
target.stunTurns = Math.max(target.stunTurns, effect.durationTurns);
target.immuneTurns = Math.max(target.immuneTurns, effect.durationTurns);
receiver.shieldValue = Math.max(receiver.shieldValue, Math.round(receiver.maxHp * value));
```

**ここだけが希望どおり「長い方／強い方を採用」。**
毒だけは別で、`poisonStacks = Math.min(5, poisonStacks + stacks)` と**スタックを積む**（上限5）。

### 延長

「残りターンへ加算」する経路は**2つだけ**。

1. **潜在覚醒「呪縛継承」**（`DEBUFF_EXTEND`）— 80%で対象の弱体効果すべてに `remainingTurns += 1`。
   `effects`・`statusEffects`・`poisonTurns`・`healBlockTurns` を一括で伸ばす
2. **才能覚醒の `buffExtendChance` / `debuffExtendChance`**（`talentExtend`）—
   これは**付与時のターン数に +1 する**もので、既存の残りターンへの加算ではない

スキル効果としての「延長」は **`COOLDOWN_EXTEND`（クールタイム延長）だけ**で、
バフ／デバフのターンを延ばすスキルは1つも無い。

### ターンの減り方

`tickEffectsAtTurnStart` が**その持ち主の手番開始時**に1ずつ減らす。
速度が高いほど早く切れる、という形になっている。

### 注意すべき差分

- **防御DOWN 50% → 75%** は32スキルすべてに効く。いまの防御式は
  軽減がDEFの値だけで決まるので、**低下幅がそのまま被ダメージに乗る。**
  別測定では防御低下75%でも勝率は+2〜3ptしか動かなかったが（`docs/final-clean-verification.md`）、
  あれは**編成を固定した1パターン**の結果で、32スキル全部を上げた時の値ではない
- **防御UP 50% → 30%** と **速度UP 30% → 20%** は**引き下げ**。
  シェルタートル・ヴァルキリア・ツリーント・ナイトなど、防護役の取り柄がそのまま削れる
- **ゴーレム「オーロラウォール」の防御UP +80%** は候補の2.7倍。
  この1スキルだけで役割が成立している可能性が高い

## 6. スキル説明と実処理

`describeSkillLines`（`src/core/skill.ts`）は effect の実値から
「攻撃力+50% (2ターン)」と**自動生成**できる。しかし各スキルの `description` は**手書き**で、
多くが数値を書いていない。

**「同じ文言なのに値が違う」例**（すべて `description` は数値を書いていない）:

| 文言 | 実装値 | モンスター |
|---|---:|---|
| 「味方全体の攻撃力を2ターン上昇させる」 | **+40%** | ナイト「しんげきのごうれい」 |
| 「味方全体の攻撃力を2ターン上昇させ、デバフを解除する」 | **+30%** | フェアリー「せいれいの加護」 |
| 「味方全体の攻撃力と防御力を2ターン上昇させる」 | ATK **+30%** / DEF **+30%** | ゴーレム「きょじんのふんぬ」 |
| 「味方全体の攻撃力と防御力を3ターン上昇させ…」 | ATK **+45%** / DEF **+40%** | ナイト「セイクリッドオーダー」 |
| 「味方全体の攻撃力とクリティカル率を2ターン上昇させる」 | ATK **+50%** / クリ率 **+20pt** | ウィスプ「ほしくずのわ」 |
| 「味方全体の攻撃力とクリティカル率を3ターン上昇させ…」 | ATK **+50%** / クリ率 **+25pt** | ウィスプ「ラディアントブレッシング」 |

**表示上は同一効果なのに、実装値が 30〜50% に散っている。**
プレイヤーからは区別できない。

逆に、11種（スコーピオン・ハーピーなど新しい側）は
`description` が「攻撃力+50% (2ターン)」と**数値入り**で、こちらは一致している。
**古い側だけが数値を伏せている**という形。

## 7. 最終回答

### 1. 現在、同一バフ/デバフで数値のばらつきがあるか

**ある。**クリダメUP（30%で5件すべて一致）以外、**全部ばらついている。**

### 2. どの効果がばらついているか

攻撃UP（5種類）・防御UP（5種類）・速度UP（3種類）・クリ率UP（4種類）・
攻撃DOWN（2種類）・防御DOWN（4種類）・速度DOWN（3種類）・被ダメージ軽減（3種類）・
無敵の持続（1Tと3T）。

突出は **ゴーレム「オーロラウォール」の防御UP+80%** と
**フェニックス「輪廻の聖炎」の無敵3ターン**。

### 3. 再付与時に重ねがけされているか

**能力値のバフ・デバフ（攻撃/防御/速度/クリ率/クリダメ）は重ねがけされる。**
`effects.push` で積み、`getEffectiveStat` が**全部合算**する。
攻撃UP30%を2回で+60%、防御UP50%+30%で+80%になる。下限は元の10%（`Math.max(0.1, 1+total)`）、
クリ率のみ100%で頭打ち。

**STATUS系（無敵・挑発など）は上書き**で、**長い方ではなく新しい方**が残る。
**フィールド保持型（スタン・毒・シールド・免疫・回復阻害・暗闇）だけが `Math.max`**。
毒はスタック加算（上限5）。

**希望のルールと一致しているのはフィールド保持型だけ。**

### 4. ターン延長処理はどうなっているか

バフ／デバフのターンを延ばす**スキル**は存在しない。加算する経路は2つだけ。

- 潜在覚醒「呪縛継承」（`DEBUFF_EXTEND`）が、対象の弱体すべてに `remainingTurns += 1`
- 才能覚醒の `buffExtendChance` / `debuffExtendChance` は、**付与時のターン数に+1**（残りへの加算ではない）

スキル効果の「延長」は**クールタイム延長のみ**。

### 5. 固定値候補へ統一する場合、どこを直す必要があるか

上の「5. 修正対象候補」のとおり。**山は `src/data/monsters.ts` の約70か所**。
加えて `src/battle/engine.ts` の潜在直書き4か所、`src/battle/damage.ts` の被クリ率2か所、
潜在の**説明文**十数件。

いちばん影響が大きいのは **防御DOWN 50%→75%（32スキル全部）** と、
**防御UP 50%→30% / 速度UP 30%→20% の引き下げ**。
引き下げは防護役・支援役の取り柄を削るので、**測ってから決めるべき。**

### 6. 共通定数化できるか

**できる。**すでに `src/data/newMonsters/shared.ts` に雛形があり、追加11種はそれを使っている。
これを `src/core/` へ移して全モンスターから参照する形にすれば、1か所で決まる。

ただし**`ATK_UP = 0.4` のコメント「既存モンスターで最も多い値に合わせてある」は事実と違う**
（実際の最多は30%で8件、40%は2件のみ）。移す時にここも直すこと。

### 7. 本番実装前に注意すべき特殊効果

1. **`CRIT_RATE_UP` / `CRIT_RATE_DOWN`（被クリ率UP/DOWN）は、付与するスキルが1つも無い。**
   型・表示名・`damage.ts` の計算（+50pt / −30pt）はあるのに、データ側で誰も使っていない。
   **固定値を決める前に、そもそも実装するかを決める必要がある**
2. **クリ率DOWN（`DEBUFF` stat=`criRate`）も0件。**候補に −30pt とあるが、現行に存在しない
3. **ancient_crystal「古代の加護」は説明文に「重ねがけで積み上がる」と書いてある。**
   重ねがけを止めると、このスキルの説明が嘘になる
4. **無敵はミミックとクロノスが「Lv最大でも1ターンのまま」と説明に明記**している一方、
   フェニックスだけ3ターン。固定値を決めるなら、この例外を残すかを先に決める
5. **防御DOWNの引き上げは、いまの防御式と相互作用する。**
   軽減がDEFの値だけで決まるので、低下幅がそのまま被ダメージに乗る
6. **強化解除は1個ずつ剥がす。**重ねがけを止めると、いま「2枚重ねだから1回の解除では消えない」
   相手が**1回で丸裸になる。**解除持ちの価値が上がる方向に動く
7. **防御無視は5系統（スキル指定・HP条件・取り巻き撃破・弱体数・パッシブ）あり、
   足さずに大きい方を1つだけ採用**している。ここは既に統一済み
