## 13. 最終結論

### **プレイヤー側の一式は、そのまま本番反映して問題ありません。**

防御式1.2・体力タイプ・防御タイプ・DEF能力付与・防御低下75%・防御UP30%は、
**すべて「採用可」**です。設計意図（通常 DEF>HP / 防御低下 HP>DEF / 防御無視 HP≫DEF）が
162個体で成立し、「DEF型が硬すぎて倒せない」「防御低下で即死する」のどちらにも振れていません。

### 再調整が必要なのは、PvE側の3点だけです

1. **塔60/80/99階の敵倍率が未指定** — 素のままだと手数が旧仕様の3〜4.5倍（72/52/100手 対 16/16/28手）。
   別測定では **DEF×0.25〜0.35** でほぼ戻ることを確認済み（80階20手、99階33手）
2. **魔人10/11階が全編成100%** — 12階だけが壁になっており、手前2階に難易度がない
3. **目覚8〜10階が易化しすぎ** — TYPICALでも分散型以外は全部100%。防御無視は9手で終わる

### 監視だけでよいもの

- **毒・防御無視**（今回は性能変更なし。魔人12階TYPICALで100%だが、新式以前から強い軸）
- **魔人12階のTYPICAL編成差**（9%〜100%）
- **魔獣12階の共通高レア**（STRONG43% / TYPICAL1%。他が65〜100%の中でここだけ低い）

### 大規模な再設計は不要です

上の3点はいずれも**敵側の倍率を決めるだけ**で片付きます。
プレイヤー側の仕様（式・タイプ・能力付与・防御低下）には手を入れる必要がありません。

## 再現方法

```
npx tsx tools/playerTypeAbilityAudit.ts --runs 200   # プレイヤー側162個体
npx tsx tools/finalCleanRun.ts --runs 200            # 塔・魔人・魔獣・目覚・防御低下
npx tsx tools/finalCleanRun.ts --only tower --runs 200
```

確定候補の定義は `tools/finalCandidate.ts`、敵倍率は `tools/finalCleanRun.ts` の
`FLOOR_SCALE` / `DEMON_SCALE` / `BEAST_SCALE` / `AWAKENING_SCALE` の1か所ずつ。
どれも**本番データではなく、測定のあいだだけ `balanceFlags` に載せる仮の値**です。
