# 保存型バックグラウンド周回

## 方針

Web/PWA、特に iPhone は、非表示・ホーム移動・完全終了時に JavaScript のタイマーを停止する。したがってリアルタイム常駐 JS や Service Worker で BattleEngine を永久実行する設計にはしない。周回ジョブを `PlayerState.backgroundFarmJob` として `localStorage` に保存し、開いている間は1周ずつ処理、復帰時は未処理の1周から再開する。

## 回数と実行可能回数

希望回数は自由入力の正の安全整数であり、固定30周上限はない。空文字、0、負数、小数、NaN、文字列を拒否する。実際の回数は各周開始時のスタミナ、日次残数、編成、解放状態で決まる。希望回数分を同期ループせず、1周後にイベントループへ制御を返す。

スタミナは各周直前に既存関数で消費し、一括前払いしない。ダイヤ・ゴールド・アイテムによる自動回復はない。自然回復は既存仕様のままだが、開始時の JST 日付を越えたジョブは停止し、翌日以降の回復・日次枠を何日も自動消費しない。育成ダンジョン（1日5回）とゴールドダンジョン（1日3回）は既存の日次残数を毎周確認する。

## 保存・オフライン・復帰

ジョブにはコンテンツ種別、対象ID/難易度、希望/完了回数、開始/最終処理時刻、JST開始日、編成個体ID、状態、停止理由、消費スタミナ、報酬集計、`inFlight` を保存する。`visibilitychange` と `pagehide` でも保存する。完全停止中は戦闘も経過時間換算の報酬配布も行わない。再ロード後はジョブを復元し、小さな非同期単位で再開する。

各周は「条件確認 → 日次枠/スタミナ消費 → `inFlight` 保存 → BattleEngine → 勝敗 → 正式報酬関数 → 完了数更新 → 保存」の順である。`SETTLING`/`inFlight` は課金済みの1戦を示し、クラッシュ復帰時に再課金しない。報酬と完了数は同じ同期処理後に一度だけ保存し、完了済み周を再実行しない。

## 戦闘・報酬・停止

通常ステージはウェーブごと、装備・育成・ゴールドダンジョンは1戦ごとに既存 `BattleEngine` と既存 BattleDefinition 構築処理を使う。勝利時だけ既存の `apply*ClearRewards` を呼ぶため、EXP、LvMAX分再分配、ファイターEXP、ゴールド、装備、モンスター、経験ピッグ、召喚書などは手動戦闘と同じ正式処理になる。敗北時は即座に停止する。装備・モンスターの自動売却はしない（現状、所持上限自体はない）。

開始時の編成個体IDを固定し、個体が欠けた場合は停止する。周回中は別のスタミナ消費戦闘を禁止し、資源競合を避ける。手動終了では完了済み報酬を保持し、未実行分は消費しない。一時停止は今回設けない。

## 対象

一度クリア済みの通常ステージ（難易度別）、装備ダンジョン、育成ダンジョン、ゴールドダンジョンが対象。未クリア対象は通常戦闘が必要。特殊な連戦・HP/CT保存を持つ試練の塔と、PvPのアリーナは対象外である。
