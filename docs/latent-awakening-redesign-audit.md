# CRIMON 潜在覚醒再設計：全72体・216候補 独立監査

> **文書の位置づけ**：2026-08-28、開始HEAD `29ae5027eeb5dd065c65c04a4b5670a20174b409` の実装を監査した、最終統合タスク向けの仕様案である。本タスクではBattleEngine、モンスターステータス、塔ステータスを変更しない。表の候補は未実装である。

## 1. 監査範囲と現行仕様

- `ALL_DISPLAYABLE_MONSTERS_DEX` は通常8種＋ガチャ限定4種を6属性へ展開した **72体**。各属性個体は属性補正後statsと、S1および属性に対応するS2/S3を持つ。素材豚・塔専用の古代悪魔/呪晶はプレイヤー潜在対象外。
- 現行候補は種族別3原案を属性へ展開する216件で、IDは `<templateId>_<ELEMENT>_latent_<1..3>`。すべてS1 (`skillSlot: 0`) の宣言データで、保存は `MonsterDevelopment.schemaVersion=1` の `latentAbilityId: string|null`。表示名は保存しない。
- 初回覚醒は候補が厳密に3件であることを検証してオーブ1個を消費。再覚醒はオーブ2個＋100,000Gを先払いし、IDをnull、`latentReselectPending=true` にしてから同じ3件を追加費用なしで再選択する。ロード時にもIDと待機状態を保持する。
- BattleEngineはDAMAGE（多段をhitループ）、BUFF/DEBUFF、STATUS、STUN、GAUGE（増減・吸収）、POISON/DOT、BURN、HEAL/LIFESTEAL/REGEN、SHIELD、IMMUNITY、CLEANSE、STRIP、HEAL_BLOCK等の正式経路を持つ。単体は選択対象、全体は生存対象を列挙し、術者側効果は最初の対象でのみ解決する。潜在後処理もスキル使用後1回なので、本案も同じ効果を再利用する。
- 実装ギャップ：現行潜在型だけでは `S1_TO_AOE`、1個だけのSTRIP、毒、スタン、強化不可、全体解除、デバフ延長、弱体数追撃、常時軽減を全て宣言できない。統合時は既存BattleEngine効果・命中抵抗・対象列挙を拡張して再利用し、潜在専用の第二状態系を作らない。

### 塔70/80/90/100Fの実コード監査

- 70/80/90/100Fはいずれも10階ボス生成経路で古代悪魔＋雑魚2体。power anchorは順に180/340/620/1100で、ボスHP・SPD倍率が乗る。
- 古代悪魔の段階能力は70Fで「自身ターン時の大回復」、80Fで自己免疫、90Fで長期戦の狂化、100Fで最終強化へ進む。従って70Fは回復阻害・ゲージ減・速度低下・スタン・毒・火力、80FはSTRIP→妨害、90/100Fは耐久・回復・毒・ゲージ・STRIP・火力という複数ルートを割り当てる。専用階判定は候補に一切置かない。

## 2. 共通解決規約

1. 「命中時」の状態異常は免疫確認後、既存の基礎発動率→的中/抵抗判定を通す。GAUGEは指定確率の独立判定。STRIPは免疫自身を含むBUFFへ先に作用できる。
2. **多段でも潜在判定は1スキル1回**。最終hit後に1回だけ判定し、hitごとの毒・スタン・ゲージ減・解除は禁止。全表の「多段」はこの規約を指す。
3. 全体化は全対象へダメージのみを配り、元S1および潜在Bの強力な追加効果はUIで選択した主対象だけ。反撃など「被hit」処理は実際に攻撃を受けた各対象で通常どおり。全体化を選ぶと単体倍率・穿甲・弱体追撃・補助分岐を捨てるため常時最適ではない。
4. 同一個体はA/B/Cから1つだけ。候補Aは攻撃範囲/火力、Bは妨害、Cは耐久/補助へ役割を分ける。評価は編成変化の大きさであり、C評価もハズレを意味しない。

## 5. 旧ID互換・統合要件

- **旧ID→新IDは全216件とも同一（identity mapping）**：例 `slime_FIRE_latent_1 → slime_FIRE_latent_1`。表示名変更でも保存IDは変えない。未知IDは勝手に別候補へ割り当てず「未選択」に正規化し、プレイヤーへ無償再選択を提示する。
- 既に選択済みの旧IDは再設計後の同じA/B/Cスロットへ解決される。意味変更を避けたい運用判断の場合は初回ログイン時だけ `latentReselectPending=true` にする移行を別タスクで検討し、オーブを再消費させない。
- 実装時はeffect type unionとresolverを拡張し、既存の `rollEffectSuccess`、`stripBuffs`、`applyStatus`、`applyHeal`、シールド、GAUGE、POISON経路を呼ぶ。全体化は既存ALL_ENEMIES対象列挙へ委譲する。デバフ延長は対象の既存turn値を更新する単一正式処理として追加する。

## 6. 弱モンスター救済の具体例

- スライムは全体化で周回役、毒/ゲージ等のBで塔制御役、Cで味方保護役となる。フェアリー/ウィスプは低ATKを純倍率で補わず、弱体追撃または穿甲、継続S1妨害、回復解除/ゲージ/盾で回復待ちターンにも価値を持つ。
- SPD72のトレントは回復阻害・速度低下・毒等で「動けば盤面を維持する」役、ゴーレムは全体化か防御無視で低ATKを補い、軽減/シールドで前衛を伸ばす。器用貧乏なナイトは範囲、制御、チーム解除を選べる。
- 一方、ドラゴン/ネメシスは数値を抑え、デバフ編成・範囲・支援とのトレードオフを要求するため、現行上位へ最強候補を集中させない。
