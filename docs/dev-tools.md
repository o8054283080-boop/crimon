# 開発の進め方と道具

このゲームは**型チェックとテストが通っても壊れている**ことが繰り返し起きた。
CSSの重なり、縦画面の崩れ、GLSLのコンパイル失敗、音が鳴らない――
どれも `tsc --noEmit` も `vitest` も素通りする。

そのたびに手で確認していたが、手作業だと**触った画面しか見ない**ため、
別の画面の崩れは依頼主に指摘されるまで気付かなかった。
ここに挙げる道具は、その穴を機械的に埋めるためのもの。

## まずこれを回す

```
npm run harness &   # 常駐サーバ(Vite + Chromium)。一度だけ起動して残す
npm run check       # 型チェック + テスト + 全画面巡回
```

`npm run check` が通れば、少なくとも
「型が合っている」「ロジックが期待どおり」「全画面が破綻していない」までは言える。

## 道具の一覧

| コマンド | 何をするか |
|---|---|
| `npm run harness` | Vite と Chromium を立ち上げたまま保つ。**これが無いと他の道具が動かない** |
| `npm run tour` | 全22画面(縦・横)を巡回し、崩れを機械的に検査する |
| `npm run tour -- --shots out` | 併せて画面ごとのPNGを保存する |
| `npm run check` | 型チェック → テスト → 巡回を通しで実行 |
| `npm run audio:check` | **自動再生の制限を有効にした**ブラウザで、音が実際に出るかを測る |
| `npm run audio:render` | 効果音を焼き直す(`public/audio/` を作り直す) |
| `npm run balance` | 装備ダンジョンの勝率を、難易度つまみを振って実測する |

## 巡回(tour)が見つけられるもの

**「格好いいか」は測れない。「壊れているか」だけを測る。**

- 横にはみ出している(縦画面で最も起きやすい)
- 押せないボタン(手前に別の要素が乗っている/画面の外にある)
- 実機で読めない文字(9px未満)
- 見出しと重なっている要素

実際にこの4種類すべてで不具合を出しているので、そこだけを検査している。
新しい種類の崩れを踏んだら、**その場で `INSPECT` に検査を足すこと。**
同じ種類の見落としを二度やらないための場所として使う。

## 開発メニュー(画面右端の「DEV」)

`npm run dev` で開いた時だけ、画面の右端に引き出しが出る。**本番には入らない。**

資源を盛る / 通常★6を全種 / 高レア★6 / 全員に★6装備 / 全ステージ解放 …… など。

何かを確かめるたびに手で状態を作っていると、
「装備ダンジョン10階の見た目を見たい」だけで何十手もかかる。
そのせいで**確認が面倒な場所ほど確認されず**、不具合が残っていた。

## 3Dの見た目を確かめる

```
node tools/probe.mjs goto /preview.html "seed=3&paused=1&roster=slime:WATER|dragon:FIRE"
node tools/probe.mjs shot /tmp/a.png
tools/audio/.venv/bin/python tools/crop.py /tmp/a.png /tmp/zoom.png 660 300 200 5
```

**小さい画像で造形を判断しないこと。** 過去に、小さいスクリーンショットを見て
「毛が消えた」と誤った報告をしている。必ず `crop.py` で拡大してから見る。

ユニットの画面上の位置は `window.__crimonStage.computeScreenAnchors()` で取れる。
カメラの構図は `frameDistance` と `camera.fov` で数値として確かめられる。

## 音を確かめる

**常駐サーバのブラウザは自動再生の制限が外れている。** そのせいで
「AudioContext を resume していない」という致命的な不具合を素通りさせた。
音の確認は必ず `npm run audio:check` を使うこと(制限を明示的に有効にして起動する)。

画面からは `window.__crimonAudio` を触れる(本番でも出している)。

- `contextState()` … "running" 以外なら、まだ音を出せる状態になっていない
- `measure(name)` … 実際に出力へ届いた音を測る。`純音らしさ` が高いほど安っぽい方向

## バランスを触る時

**勘で数値を置かない。** `npm run balance` で候補を振って実測してから決める。

装備ダンジョンのボスHPを5倍にした時、`powerScale` を据え置いたら
1階の勝率が0%になった。数値どうしが掛け算で効くので、
1つ動かすと別のところが壊れる。
